| 5 | CLAUDE.md — конвенції найменування | Окремий розділ з конвенціями найменування є |
| 6 | CLAUDE.md — do not touch (міграції) | Міграції явно позначені як зона «do not touch» |

| 11 | Доказ у записі INSIGHTS.md | Кожен запис має file:line і дату |
| 12 | Cost у списку Pull Requests | Сума вартості всіх успішних прогонів по PR; немає прогонів — значення порожнє |
| 13 | Cost на вкладці Agent runs | Кожен прогін у Timeline показує свою вартість |
| 14 | Cost у сайдбарі трасування прогону | Окремий стат-блок COST у Trace drawer → Stats |
| 15 | 5-фазний цикл роботи | Initiation → Planning → Implementation → Validation → Completion пройдені |
| 16 | Лічильники findings за severity | Вкладка "Agent runs" має ДВІ секції: "Timeline" (плитки прогонів і комітів у хронології — кожна плитка теж показує свої severity-іконки, але без кліку) і "Review runs" (картки по прогону, розгортаються). Лічильники з цього критерію — саме в "Review runs": (1) відкрити PR → (2) вкладка "Agent runs" → (3) секція "Review runs" → (4) клікнути на картку прогону, розгорнути → (5) під вердиктом і PR SCORE — рядок пілюль «N CRITICAL · N WARNING · N SUGGESTION» (тільки ті severity, що реально є) |
| 17 | Лічильники відповідають реальності | У тій самій розгорнутій картці прогону: число на пілюлі = кількість карток-знахідок цієї severity, виведених нижче в цій же картці |
| 18 | Фільтр знахідок по severity | У тій самій розгорнутій картці прогону: клік по пілюлі лишає нижче лише знахідки цієї severity; повторний клік знімає фільтр і повертає повний список знахідок цього прогону |
| 19 | Підрахунок без LLM | Числа «N CRITICAL · N WARNING · N SUGGESTION» рахуються групуванням уже наявних findings за полем severity (простий COUNT/filter). Жодного нового звернення до LLM при відкритті сторінки чи перемиканні фільтра |
| 20 | Попап «N FINDINGS IN THIS RUN» (сторінка СПИСКУ PR, не деталей!) | На сторінці списку Pull Requests (де перелічені всі PR), при наведенні курсора на severity-іконки в колонці FINDINGS конкретного рядка PR — з'являється спливаюче вікно (popover) із заголовком «N FINDINGS IN THIS RUN» |
| 21 | Прев'ю знахідки в попапі — read-only | В тому самому попапі зі списку PR (не в акордеоні на сторінці PR!) кожне прев'ю знахідки показує лише текст: severity-іконку, заголовок, категорію, file:line, % confidence, короткий опис — без жодних кнопок |
| 22 | Картка знахідки з Accept/Reject — ІНШЕ місце (сторінка PR, акордеон Review runs) | Це вже не попап зі списку PR, а розгорнута картка прогону на сторінці конкретного PR (вкладка Agent runs → Review runs) — там у кожної знахідки є кнопки Accept і Reject |
| 23 | Знахідки в сайдбарі Trace and Logs | Видно не лише cost/stats, а й самі знахідки |
| 24 | docs/ і specs/ по кожному пакету | Реальний контент з лабораторної, не порожні README-стаби |
