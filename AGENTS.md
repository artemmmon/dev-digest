# DevDigest

Local AI pull-request reviewer: imports PRs from GitHub, indexes the repo, runs LLM
agents over the diff, stores grounded findings. Course starter template — lessons
L01–L08 add features back (README → "What you build in the course").

## Stack
- Node ≥ 22 · pnpm ≥ 10 · Docker (Postgres 16 + pgvector) · TypeScript 5.7 · Vitest 2 · zod 3
- server: Fastify 5, Drizzle ORM 0.38, Octokit 4, p-queue 8, ast-grep, dependency-cruiser
- client: Next.js 15 (App Router), React 19, TanStack Query 5, next-intl 3, Tailwind 4
- LLM: OpenRouter by default (`deepseek/deepseek-v4-flash`); OpenAI / Anthropic SDKs

## Packages
No monorepo workspace: each package has its own `package.json` + lockfile.
Each has its own `AGENTS.md` — read it before working in that package.

| Folder | Role | Package manager |
|---|---|---|
| `server/` | Fastify API :3001 — all I/O: DB, GitHub, git, jobs, SSE, repo-intel | pnpm |
| `client/` | Next.js UI :3000, talks to the API over REST + SSE only | pnpm |
| `reviewer-core/` | Pure review engine (prompt → LLM → grounding), no build step | **npm** |
| `e2e/` | Deterministic browser flows (agent-browser CLI, no LLM) | **npm** |

## Commands
```sh
./scripts/dev.sh              # docker → migrate → seed → api + web
./scripts/dev.sh --db-only    # Postgres + migrate + seed only
./scripts/e2e.sh              # hermetic e2e on alternate ports
```
Per-package build/test commands live in each package's `AGENTS.md`.
Every package exposes the same three checks: `typecheck` · `lint` · `test`.

## Naming
- Files `kebab-case.ts`; a file whose default export is a React component is
  `PascalCase.tsx`. Folders are `kebab-case`, except a feature component's own folder.
- Server module: `src/modules/<kebab-name>/`, layered `routes.ts` → `service.ts` →
  `repository/`; pure helpers beside them (`cost.ts`, `findings.ts`).
- Client feature component: `_components/<PascalName>/<PascalName>.tsx` + `index.ts`;
  cross-cutting chrome lives in `src/components/<kebab-name>/`.
- Tests sit next to their subject as `<subject>.test.ts(x)`. A server test that touches
  the DB **must** end in `.it.test.ts` — that suffix is what splits the CI lanes.
- i18n: one file per feature, `client/messages/en/<camelCase>.json`, `camelCase` keys
  nested by UI area.
- Docs: specs `specs/NN-short-name.md` · decision records `docs/NNNN-short-title.md` ·
  guides `docs/kebab-case-topic.md` · e2e flows `e2e/specs/NN-name.flow.json`.
- DB tables and columns are `snake_case` (`agent_runs.cost_usd`) and the Zod wire
  contracts keep that spelling; only React props and locals are `camelCase`.
- Git: branches `lesson-NN`, commit subjects `type: imperative summary`
  (`feat` · `fix` · `docs` · `chore`).

## Cross-package rules
- Zod contracts are **copied**, not shared: `server/src/vendor/shared` (canonical,
  also read by reviewer-core) and `client/src/vendor/shared`, kept content-identical
  (the client copy has `.js` stripped from relative imports — its bundler can't
  resolve them for a cold runtime import; the server needs them for Node ESM).
  Edit the server copy, then `./scripts/shared-contracts.sh sync`; CI runs `check`.
- Cross-package imports go through tsconfig path aliases (`@devdigest/shared`,
  `@devdigest/reviewer-core`), never relative `../../other-package` paths.
- CI is path-filtered per package (`.github/workflows/`); `reviewer-core/**`
  also triggers `server-unit` because the server type-checks against its source.

## Do not touch
- `server/clones/` — runtime git checkouts, includes a full copy of this repo.
  **Exclude it from every grep/search.**
- `server/src/db/migrations/` — generated by `pnpm db:generate`; never hand-edit.
- `docker compose down -v` — deletes the `devdigest_pgdata` volume with real data.
- Lock files (`client/pnpm-lock.yaml`, `server/pnpm-lock.yaml`,
  `reviewer-core/package-lock.json`, `e2e/package-lock.json`) — never hand-edit or
  merge by hand; regenerate with that package's own manager (pnpm here, npm there).
- `temp/` — the user's local notes (git-ignored).
- `CLAUDE.md` files — symlinks to the `AGENTS.md` beside them, for Claude Code.
  Edit `AGENTS.md`; never replace a link with a copy.

## Documentation map
Read on demand when the task matches — do not preload.
- `README.md` — product overview, quick start, troubleshooting
- `TESTING.md` — test strategy, suite map, test conventions
- `docs/` — cross-package docs; `docs/agent-prompts/` — reviewer agent prompts, model choice
- `docs/demo-video.md` — how to record a narrated demo of a lesson
- `specs/` — cross-package feature specs (check before starting a feature)
- `INSIGHTS.md` — cross-package gotchas and non-obvious decisions

## Keeping docs alive
- Before changing code in a module, read its `INSIGHTS.md` — the one exception to
  "do not preload"; that's where past sessions left their lessons.
- Found something non-obvious (a dead end, a quirk, an error + fix, an unwritten
  convention, an open question)? Record it right away with the `engineering-insights`
  skill — it picks the module's `INSIGHTS.md` and section. Don't wait to be asked.
- Implementing a spec? Update its `Status` line when you start and when you finish.
- Keep every `AGENTS.md` ≤ 100 lines: map, not documentation. Details go to `docs/`.
